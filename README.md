# swift-russh

Swift SSH and SFTP client built on [russh](https://github.com/Eugeny/russh) and
[russh-sftp](https://github.com/AspectUnk/russh-sftp). It began as a drop-in
replacement for [swift-libssh](https://github.com/kosolabs/swift-libssh) and
keeps its overall shape, but the API has since diverged; breaking changes are
listed in the [changelog](CHANGELOG.md).

## Layout

| Path | What it is |
| --- | --- |
| `rust/` | The `russh-ffi` crate: sessions, SFTP and exec channels, exported with [UniFFI](https://mozilla.github.io/uniffi-rs/) |
| `Sources/CRusshFFI.xcframework` | The crate built as a universal (arm64, x86_64) static library |
| `Sources/RusshFFI` | Swift bindings generated by UniFFI |
| `Sources/SwiftRussh` | The public Swift API |
| `Sources/SwiftSSH` | CLI for uploads, downloads and stress runs |
| `Tests/SwiftRusshTests` | Tests, run against the shared SSH test server |

The Rust version and targets are pinned in `rust/rust-toolchain.toml`; rustup
installs them on first use.

`build.sh` rebuilds the XCFramework and regenerates the bindings. Run it after
changing anything under `rust/`, and commit the regenerated bindings; CI fails
if they don't match the Rust code.

The XCFramework is not committed. `Package.swift` uses the local build in
`Sources/CRusshFFI.xcframework` when it exists and otherwise downloads the
binary attached to the release. SwiftPM caches manifest evaluation, so after
deleting the local build, resolve with `--manifest-cache none` or clear
`.build`.

## Releasing

Releases are cut by merging release-please's release PR, as in swift-libssh.
Before 1.0, breaking changes bump the minor version rather than releasing 1.0
(`bump-minor-pre-major` in `release-please-config.json`).

1. When release-please pushes the release branch, **Pin Binary** builds the
   XCFramework, keeps the zip as an artifact named after its checksum, and
   commits the release URL and checksum to `Package.swift` on that branch.
2. Until that commit lands, CI's *Functional Tests* check waits (pending) on
   the release PR, so it can't be merged with the previous release's binary.
   Once the pin lands, that run cancels itself and a new run tests the pinned
   commit. If Pin Binary fails, the check fails.
3. Merging tags that commit, so the tag already points at the right binary.
   **Release** then attaches the matching artifact to the GitHub release after
   verifying its SHA-256.

Both workflows need the `swift-russh-release` environment with the
`RELEASER_PRIVATE_KEY` secret, and the releaser app installed on the repo. The
environment must allow the `main` and `release-please--*` branches. Pin Binary
runs on pushes rather than pull requests because GitHub checks pull request runs
against `refs/pull/<n>/merge`, which no branch policy can safely allow.
Merge the release PR within 90 days of its last update, or the artifact
expires; pushing to the PR branch rebuilds it.

## Testing

```sh
just test          # starts the shared test server on port 2248, then swift test
just stress
just stress-tree
```

The test server is shared with swift-libssh and SSHadow; keep
`scripts/start_test_server.sh` identical across the three repos.

## Behaviour that differs from swift-libssh

- **Errors.** Match `SSHError` by its reason rather than its message, for
  example `catch SSHError.sftp(.noSuchFile, _)` or
  `catch SSHError.connectionFailed(.refused, _)`. The message is
  human-readable detail, may change, and is the error's `localizedDescription`.
  Local file failures in `download` and `upload` throw Foundation's own errors.
- **Host keys.** `connect` takes a required `hostKey:` validator:
  `.expecting(key)` for a key stored earlier (for example from
  `SSHClient.hostKey(host:)`), a closure for your own policy, or
  `.acceptingAny`. swift-libssh accepted any key unless you passed one.
- **Concurrency.** Requests on one SFTP session run concurrently instead of one
  at a time, so independent operations issued from separate tasks overlap.
- **Dead connections.** Keepalives are sent every `timeout / 4` seconds and the
  session closes after three go unanswered, so a stalled server is detected
  within about `timeout` even when the client is idle. SFTP requests also time
  out after `timeout`, rounded up to whole seconds.
- **Ciphers.** AES-GCM is preferred over ChaCha20-Poly1305, as libssh does.
  russh's default order puts ChaCha20 first, and it is several times slower.
- **Cancellation.** Cancelling a Swift task does not interrupt a call that is
  already running in Rust. The call finishes or times out, as libssh's blocking
  calls do. Channel and file streams, directory iteration, `download` and
  `upload` check for cancellation between chunks and throw `CancellationError`,
  where swift-libssh ended the stream early and reported success.
